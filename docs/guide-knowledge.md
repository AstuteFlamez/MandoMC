# M4-ND conversation and gameplay knowledge

M4-ND specializes in verified MandoMC gameplay, Star Wars lore, relevant Minecraft mechanics and friendly droid conversation. Greetings, farewells and thanks use configurable in-character replies without AI quota. Lore and vanilla Minecraft replies may use the model's knowledge, acknowledge uncertainty and distinguish canon from Legends when asked. A small maintained canon primer anchors common character identity/training facts; other Star Wars subjects remain available. Lore and vanilla facts never establish server mechanics. The droid cannot perform actions or look up live real-world information.

## Exact release knowledge

Every `scripts/build.sh` invocation regenerates `guide-repository.json` and `guide-public.json.gz` in ignored build resources. The manifest records the exact full source commit, clean/modified state, and all approved tracked public paths with byte lengths and SHA-256 hashes. The JAR bundles the corresponding source bytes. On startup, the guide worker verifies the bundle against its own manifest and builds an offline index; no network access is needed for normal knowledge startup.

Approved sources include public gameplay documentation, native recipe/loot/shop/item/vehicle/event configuration, relevant gameplay code, MythicMobs definitions/skills and WeaponMechanics weapon/ammunition definitions. Agent instructions, runtime data, credentials, deployment documentation and administration internals remain excluded. Only public utilities limits are explicitly admitted from admin configuration. No arbitrary URL or local path can be queried.

The generated encyclopedia retains an entity's name with its nested statistics, uses reviewed common configuration instead of duplicate defaults, and calculates crate percentages from the total configured weight. Spawn records join the native encounter roster to the configured world/biome/distance conditions. Scripted attack damage remains separate from base melee damage. Materials use the same acquisition sources and recipes as `/recipes`, including direct ingredient acquisition notes. Vocabulary aliases and conservative typo matching improve item/mob lookups. Relevant public source passages supplement structured records; the model receives bounded evidence rather than entire files.

Downloaded/bundled source is evidence, never instructions. Current verified notes and configuration outrank historical documentation. Historical, rollout, verification and implementation sections are excluded from player context. Pending/deferred features are unavailable. Internal identifiers and world aliases are translated into player language.

## Conversation and live answers

Topic routing selects retrieval context; it does not authorize a subject. Every generated reply semantically classifies the current request into MandoMC, Star Wars, Minecraft, conversation, outside or clarify. The provider is asked for a strict schema-bound response, which must also pass local validation before any generated answer is displayed. Outside/clarify generated text is discarded and replaced with maintained character text; malformed or unclassified replies use the existing safe fallback. Real-world brands, universities, geography, news, homework and unrelated advice are outside scope. Mentioning a permitted keyword does not establish relevance. Mixed questions receive only their supported portion; ambiguous terms request context. Both maintained redirects and clarifications invite in-domain context, so an unrecognized name still receives a useful next step if the model classifies it outside. First-base questions use maintained beginner guidance, including when an unrelated preamble is present. Unknown server mechanics retain an explicit knowledge fallback rather than using general knowledge to invent an answer. Rejected or ambiguous requests clear their topic context and refund the personal answer/cooldown while retaining actual shared token cost and global request spacing. Short supported follow-ups reuse only that player's previous topic for five minutes, bounded to 256 players and cleared on disconnect/restart. Follow-ups and personal wording bypass the shared static-answer cache.

A player's own balance is read directly from CreditLedger on the server thread. Current/next event labels, scheduler state and the next scheduled start are read directly from EventManager. These replies bypass AI, shared caching and quotas. Other players' balances, inventories, locations and clan records are not queried. Exact acquisition, beginner, Fortune and death responses also retain deterministic verified guidance. AI replies are plain text, up to four short sentences/100 words, with the existing private delivery, cooldown and daily limits.

## Every production push

`AGENTS.md` requires knowledge upkeep as part of every production release. When gameplay changes, update public acquisition notes/explanations, add new public source areas to both reviewed allowlists when needed, and add representative regression questions. Do not duplicate balance values in prose when they can be derived from authoritative configuration.

The build always regenerates the bundle. `scripts/check-guide-knowledge.py` verifies the packaged JAR's exact commit, complete approved source set, hashes and bundled contents against the checkout. CI runs `--release`, which additionally requires clean committed source, before retaining the build and again immediately before production upload. The local production upload command enforces the same check and requested commit identity. Stale, tampered, incomplete, modified or wrong-version release knowledge blocks the upload.

A production push stages the next JAR/configuration. Knowledge becomes active at the normal production restart, together with that release's gameplay. After restart, verify the `M4-ND public knowledge ready` marker for the exact deployed commit and ask representative questions for changed content. Do not mark release knowledge current until those checks pass. Production promotion and manual restart retain the existing workflow.

## Fallback and verification

If the bundle is absent/corrupt, a clean build may use a validated same-commit cache or the exact public GitHub archive. Redirect/download/decompression bounds and source hashes remain enforced. Modified development builds may use their own verified bundle but cannot fetch or reuse a released cache. There is no latest-branch or older-release fallback. If every verified source is unavailable, written guidance remains available; conversational failures also have a configured response and do not consume a personal answer.

Unit/tooling tests cover source privacy, exact-build isolation, bundle integrity, overrides, structured statistics, probabilities, acquisition links/typos, scope separation, follow-up isolation and release rejection cases. Native Paper checks exercise real player questions, live authorities, quota-free conversation, the offline encyclopedia and real AI responses before development deployment.
