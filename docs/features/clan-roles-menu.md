# Feature: Clan roles, roster menu and connected territory
Status: verified implementation; coordinated rollout pending
Branch: bilal/tutorial-handbook

`/c` opens an informational native menu; `/c help` lists every command. Clan members see name/status, their role, member/claim counts, home, active raids/warpoints and actual player heads with role and online status. Active raids sort before ordinary rival scores. Head profiles load asynchronously with a three-second fallback and ten-minute request cache. Member pages also support grandfathered larger rosters. No-clan players see create/join/help guidance. Public home labels say Mandalore/Tatooine rather than exposing internal Review keys.

The hierarchy is Leader > Officer > Member > Recruit. Leader controls promotion/demotion one step at a time, leadership transfer, home and disband. Transfer makes the previous leader a Member. Officers can claim/unclaim/unclaimall, invite new recruits and kick lower ranks; they cannot kick another Officer/Leader or change ranks. Members retain ordinary clan access. New joins start Recruit; all legacy nonleaders without stored roles remain Member. Existing leader UUID is the sole leadership authority. Legacy co_leader identifiers migrate to Officer; that name is not displayed.

Recruits retain Member behavior except access to clan storage. Opening/using storage blocks, chest variants, hoppers and storage entities inside clan claims is denied. The user explicitly approved denying storage breaking as well. Current permission is rechecked on opening, clicking and dragging, so an already-open inventory cannot bypass demotion/kicking. Existing double-chest, cross-claim automation and mobile-hopper guards remain. Ordinary editing and non-storage workstations remain available. Unclaimed storage is unaffected. Public-loot abandonment opens storage to everyone, and existing Creative staff overrides remain. Beskar's narrow EventMining allowance and event-node touch exclusion are preserved.

Defaults and installed configuration become four players and four chunks. Existing over-limit clans retain members and cannot invite/accept further joins until below four. All acceptances check the current authoritative size, including pending invitations. The existing eleven-page handbook changes only its clan capacity line from five to four players and updates an issued marked copy through `/tutorial`.

After the first claim, new land must share a cardinal edge with an existing claim in the same world. Diagonal contact is insufficient. A full unclaimed chunk must still separate rivals, including diagonals; protected-zone and border buffers also remain. Ordinary unclaim cannot increase the number of connected components. Existing disconnected claims are retained; removing isolated components or leaf chunks is allowed. Unclaimall/disband intentionally clear whole territory.

The menu never adds virtual icons to a player's inventory. Shift/number/offhand/double clicks and drags are cancelled across the complete view. Its only click actions are help and roster pagination; management remains explicit commands. Full player inventories remain intact. Cursor items, crafting ingredients and other open inventories defer opening before any closure/return can drop items. Roster refresh changes only differing icons, and pending profile work cannot reopen a closed view. Lifecycle cleanup unregisters its listener/timer and closes owned empty virtual views.

Roles are an additive map in schema-1 clan storage; missing values mean Member. Role IDs are persisted atomically through the existing main-thread snapshot/IO worker. Invalid outsider/duplicate-leader roles fail validation. There is one role authority, not GUI/head metadata. No player/member/claim eviction occurs during migration.

The sidebar's bottom serverinfo has one gray frame, exactly `play.mandomc.net`, in normal and combat layouts. Other animations, rows, territory colors and the chosen flag remain unchanged. No pack update is needed.

Verification: 216 Java tests; 422 native GUI/command/storage/connected-claim/buffer assertions, including a live tick/profile refresh with all owned slots preserved; two native starts each pass 16 migration/persistence assertions for legacy five-member/disconnected clans and Officer/Recruit ranks; 129 native HUD/NPC/mechanism/color/footer assertions. The initially disconnected fake client was correctly immobile to vanilla, so the long-lived fixture now uses an in-memory connected channel and real load acknowledgements. No production workaround was needed. Overlay tooling verifies old public API signatures and rejects the known missing-NPC-method regression.
