# Feature: recovered E-11
Status: implemented; client playtest pending
Branch: bilal/e11-blaster (stacked on the unmerged spawn-teleport branch)

## Player experience
One usable E-11, retaining the supplied server's tuning: right-click fires, left-click aims, Q reloads. A magazine holds 30 shots; reloading takes 45 ticks and uses Standard Plasma Cells. Normal/aim/sprint poses, red bolts, firing and reload sounds come from the original pack. Acquisition, starter kits, other blasters and Clans remain deferred.

For operator testing: `/wm get E11`, then hold it and `/wm ammo 64`. Travel to survival and leave the protected landing to fire. Check in survival mode so creative ammo behavior does not hide consumption issues. Regular use permission is `weaponmechanics.use.E11`; administrative item-grant permissions should stay restricted. Verify protection as a non-op: WorldGuard operators can bypass regions.

## Rules and ownership
WeaponMechanics owns weapon identity, projectiles, damage, ammo, reloading and pose selection. No new MandoMC gameplay Java is needed. WorldGuard `weapon-shoot: deny` and `weapon-damage: deny` protect SpawnWorld and the one-chunk survival landing, including incoming bolts. Both regions configure `weapon-shoot-message` as “You can’t shoot in a safe zone.” Existing Bukkit damage events remain the travel combat-tag boundary; multiplayer tag/reload interaction still needs a client test.

Weapon tuning is copied, not rebalanced: 9 shots/second, projectile speed 90, base spread 4.5, damage 0.5, 15-tick equip delay, 1.5 scope zoom. Vendor YAML remains the parameter source. Safe deployment uses a stopped server and restart.

## Files and installation
Copy these tracked templates into the ignored runtime WeaponMechanics folder:

| Template in server/config/common/weaponmechanics | Destination under server/runtime/plugins/WeaponMechanics |
| --- | --- |
| e11.yml | weapons/mandomc/e11.yml |
| standard_plasma_cells.yml | ammos/standard_plasma_cells.yml |
| redlaser.yml | projectiles/redlaser.yml |

The newer vendor version loads ammo/projectiles from separate registries. The old `redlaser.Projectile` reference becomes `redlaser`, and its extra nested `Projectile` section is removed. Existing sample weapons are untouched; E11 is the only added weapon.

Deploy the existing `worldguard-spawn.yml` and `worldguard-landing.yml` templates to their documented runtime region files. Preserve unrelated local regions when applying to a different server. The original supplied backup is unchanged.

## Resource pack and legacy differences
The existing E-11 model/texture/poses are reused. Explicit `Item_Model` keys pair with the original custom model data: default 2, scope 1002, sprint 2002; plasma cells 25; red bolt 40. This avoids overriding vanilla hoes or echo shards. Model keys use `mandomc:blasters/e11`, `_scope`, `_sprint`, `mandomc:ammo/standard_plasma_cells` and `mandomc:projectiles/redlaser`.

Only four original OGG files are added: `shoot/e-11`, `reload/start`, `reload/complete`, `misc/zoomrifle`. The old `blaster.scope.in/out` events do not exist in the supplied pack; both use the existing rifle zoom sound. The original name, description and rarity/category badges are retained. E-11 and plasma-cell lore use the accepted [item tooltip standard](../style-guide.md#item-tooltip-standard): blank line after badges, gray description, compact yellow keybind controls when applicable. The three common/weapon/ammo badge textures live under `mandomc/textures/font/item_labels/`; obsolete drop/reload providers and textures are removed. No unrelated HUD or shader assets are imported. Existing items retain their stored lore: use `/wm get E11` for a fresh updated item. Per-asset hashes and provenance are in resource-pack/sources.json.

No WeaponMechanicsCosmetics or WeaponMechanicsPlus JAR was found in the supplied legacy plugins tree. Optional muzzle flash, splash/whiz and third-person pose settings are omitted for now; core first-person aiming/sprint skins work without those add-ons. The missing `fx.blaster_whiz` sound is consequently not added. Installed vendor versions remain WeaponMechanics/MechanicsCore 4.3.1 and PacketEvents 2.14.0; no old or purchased binaries are committed.

The pack is published as a versioned feature-branch prerelease using the existing ZIP/manifest contract; main is not merged. Server startup selects the newest compatible published pack. See resource-pack/README.md for normal hosting and rollback behavior.

## Verification
Build the main project with `./scripts/build.sh`, build the pack with `./scripts/build-resource-pack.py`, and run `python3 -m unittest discover -s scripts/tests -v`.

The temporary `scripts/integration/E11Probe.java` passed 52 assertions. It checks actual generated items, three pose models and custom model data, ammo registry/empty-magazine handling, loaded projectile appearance, WorldGuard boundaries and real entity hits inside/outside the landing. It removes its temporary entities and does not touch player inventories. It is not an authenticated multiplayer or rendered-client test.

To repeat locally, first run `./scripts/build-arrival-probe.sh` to populate the existing Paper/WorldGuard classpath. Compile E11Probe against that classpath plus the pinned MechanicsCore and WeaponMechanics runtime JARs, package it with a Bukkit plugin.yml (main `net.mandomc.verification.E11Probe`, API `26.1.2`, dependencies WeaponMechanics, MechanicsCore, WorldGuard, Multiverse-Core), and install only while stopped. Remove the probe JAR and restart after checking `E11 PROBE PASSED` in the log. Never leave test probes installed during ordinary play.
