# Weapon reload indicator

Outcome: while a real WeaponMechanics reload runs, show `Reloading [||||||||||] 1.2s` in the actionbar. All vendor weapon titles use the same integration, including main hand and offhand. Existing MandoMC notices (including jetpack fuel, combat protection, saber and vehicle messages) hold priority for 1.5 seconds after their latest update. The post-Boba `BobaEquipmentFeature.equipment().ownsActionBar(player)` owner also takes precedence throughout thrust and its full three-second critical fuel reservation. That API is required at startup. No cooldown is added to other abilities.

## Authority and lifecycle

WeaponMechanics 4.3.1 owns acceptance, duration, ammo and scheduled tasks. The integration observes `WeaponReloadEvent` at MONITOR, retains the final event, and checks `HandData.isReloading` on the next server tick before displaying anything. It reads `getReloadCompleteTime` (open + reload + close) and `getReloadElapsedTime` (capped by server ticks since the event so lag cannot advance the display ahead of tick-scheduled completion), checks the weapon still occupies the event's hand, and clears on vendor completion/cancellation. Full magazines, vetoed starts and rejected/no-ammo starts never acquire display ownership. Restart replaces the prior display for the same player/hand. Main hand takes display priority when both hands reload. World change, death, disconnect and plugin disable discard observer state. A critical message cannot be erased by reload cleanup.

Paper 26.1.2 supports grouped item cooldowns, but setting one is a real item-use cooldown. Isolating same-material weapons additionally requires changing the item's USE_COOLDOWN component. We select the requested fallback to preserve item metadata, existing groups, right-click/fire/reload behavior and other items. No weapon/item/ammo/cooldown/task mutators are called. The vendor's existing `Show_Time.Reload` configuration is for its absent optional addon; core 4.3.1 does not implement that overlay.

API references: [Paper HumanEntity](https://jd.papermc.io/paper/26.1.2/org/bukkit/entity/HumanEntity.html), [UseCooldown](https://jd.papermc.io/paper/26.1.2/io/papermc/paper/datacomponent/item/UseCooldown.html), [WeaponMechanics reload module](https://cjcrafter.gitbook.io/weaponmechanics/weapon-modules/reload). Installed vendor bytecode was inspected for event ordering, `HandData` task/elapsed ownership, chain completion and cancellation.

## Release boundary

The canonical checkout is older than the composed deployed release. Do not install this branch's full Maven JAR. `scripts/build-reload-overlay.py` compiles only the new classes against a hash-pinned current release. Its classfile transform adds lifecycle hooks after the current Boba enable call and before disable returns. It mechanically replaces each current MandoMC `Player.sendActionBar(Component)` call with `ActionBars.send(Player, Component)`; each existing method body and API otherwise stays intact. Unknown actionbar signatures or missing lifecycle anchors fail the build. Every other JAR entry remains byte-identical. No resource-pack change or vendor config change is required. Rebuild after any Boba patch; never restore an earlier Boba class to deploy this feature.

Before a future unified full-source release, apply the same ActionBars call replacements to the integrated source and invoke ReloadIndicator.enable/disable at those lifecycle boundaries. The scoped overlay is the reviewable source of these additions while feature source integration remains pending.

## Verification

Run `scripts/build.sh` for compilation/tests. `scripts/build-reload-probe.py` builds a disposable-only native Paper probe using generated vendor weapons, actual `tryReload`, real scheduled reload completion/cancel, offhand/switch/full-magazine cases and priority leases. Never install the probe into the shared player server. The exact post-Boba candidate passed 105 native assertions: all nine current reloadable titles, real outgoing countdown packets and advancing time, real completion/ammo, restart/veto/cancel/offhand/switch/no-ammo/full-magazine handling, actual Boba ownership through its full reservation, a 300ms server stall, world-change/logout cleanup callbacks, and native player death. The logout callback is invoked directly for the native test actor because it has no third-party join session; this avoids sending unrelated vendors a fictional quit. The shared server is never used for these actors. A real connected client remains necessary to confirm visual readability; native server assertions do not prove pixels.
